# Как сдать работу

**Рабочая ветка → файлы → PR → ссылка в таблице → замечания → принятие.**

PR — страница сдачи с изменениями и обсуждением. `main` — основная версия проекта; рабочая ветка содержит изменения текущего этапа.

## Подготовка

1. Создайте аккаунт [GitHub](https://github.com) и репозиторий из [шаблона](https://github.com/project-seminar-2026/vkr-template): **Use this template → Create a new repository**, свой аккаунт, имя проекта, **Public**. **Include all branches** не включайте.
2. Запишите свой username и репозиторий в таблицу курса. Ссылку на таблицу выдаёт преподаватель.
3. В [настройках уведомлений](https://github.com/settings/notifications) включите email для обсуждений, в которых участвуете. Проверяйте PR и почту после сдачи.

Для командного проекта можно использовать один репозиторий. Его создаёт один участник и добавляет остальных через **Settings → Collaborators** с доступом на запись. Совместный результат сдавайте одним PR с авторами и вкладом каждого. Каждый участник указывает этот PR в своей строке таблицы. Личные части ВКР сдавайте отдельными PR.

## Сдача через сайт

1. **Создайте ветку.** На вкладке **Code** нажмите переключатель `main`, введите имя, например `s7-lab2`, и выберите **Create branch … from main**.
2. **Добавьте материалы.** Проверьте выбранную ветку. Откройте нужную папку, выберите **Add file → Upload files** и сохраните файлы через **Commit changes**. Предпочтительный формат лабораторных — **Markdown**; DOCX и PDF также допускаются. Для Markdown можно выбрать **Add file → Create new file**, назвать файл `report.md`, написать текст и проверить его через **Preview**. Сохраните изменения в рабочую ветку; существующий файл редактируется значком карандаша.
3. **Откройте PR.** Нажмите **Compare & pull request** или **Pull requests → New pull request**. Направление: **base: main**, **compare: ваша ветка**, обе в вашем репозитории. Укажите семестр и этап, заполните описание и нажмите **Create pull request**, без статуса Draft.
4. **Зарегистрируйте сдачу.** Вставьте адрес PR в свою строку таблицы и колонку этапа. Ссылка должна содержать `/pull/` и номер.

Для **ЛР 2** используйте [пояснение по сдаче](lab2.md) и [шаблон `docs/research/report.md`](../docs/research/report.md). Для **ЛР 3** — [пояснение по сдаче](lab3.md) и [шаблон `docs/design/report.md`](../docs/design/report.md). Актуальные условия обеих лабораторных — по ссылкам на Google Диск в этих пояснениях.

## Проверка и исправления

Если научный руководитель уже есть, желательно сначала показать работу ему и отправить ссылку на PR. Его ревью не является условием сдачи. Лабораторные проверяют преподаватели семинара; одобрение руководителя не заменяет их решение о зачёте.

Читайте замечания в **Conversation** и **Files changed**. Для Word и PDF в отзыве указывается документ, раздел или страница.

Исправляйте файлы **в той же ветке, под тем же именем**. PR обновится, ссылка останется прежней. Ответьте в обсуждении, что исправлено.

После принятия актуальной версии преподавателем семинара нажмите **Merge pull request → Confirm merge**. Следующий этап начните новой веткой из обновлённой `main`.

<details>
<summary>Команды для сдачи через Git</summary>

Установите [Git](https://git-scm.com/downloads) и [GitHub CLI](https://cli.github.com). Замените `OWNER`, `REPO` и путь отчёта своими значениями. Выполняйте команды по одной.

Один раз войдите и скачайте репозиторий:

```bash
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
gh repo clone OWNER/REPO
cd REPO
```

Для нового этапа:

```bash
git switch main
git pull --ff-only
git switch -c s7-lab2
# Сохраните отчёт в docs/research/report.md
git add docs/research/report.md
git commit -m "Добавить обоснование темы"
git push -u origin s7-lab2
gh pr create --base main --head s7-lab2 --web
```

Заполните PR и внесите ссылку в таблицу. Для исправлений в той же ветке повторите `git add`, `git commit` и `git push`.

Если Git попросит имя и почту автора:

```bash
git config --global user.name "Ваше имя"
git config --global user.email "YOUR_EMAIL"
```

При ошибке остановитесь и сохраните текст ошибки для обращения за помощью.

</details>

## Важно

- Публичные файлы видны всем. Не загружайте личные документы, скриншоты my.itmo.ru, закрытые данные, пароли и ключи.
- Отчёт должен быть в ветке PR, а не только вложением к комментарию.
- Анкета и отчёт по ГИА сдаются отдельно — см. [карту заданий](assignments.md).
